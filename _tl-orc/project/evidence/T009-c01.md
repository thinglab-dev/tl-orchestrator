## Orientação recebida (íntegra)
## 1. Resposta direta

**São requisitos a consolidar, não mais manifestações isoladas para corrigir uma a uma no protótipo.** Evidência: quatro rodadas consecutivas (r02→r05) tiveram achado central na mesma classe — "procedência das entradas" — cada uma revelando um ângulo novo do mesmo defeito estrutural: r02 R1/R2 (localização ignorada para `local_ids`/`proxy_ids`, T009-r02.md:40-52); r03 R1/R2 (ocorrência literal e âncora por prefixo bastam, T009-r03.md:40-52); r04 R1 (envelope ausente para `roles`/`authors`/`chains`/`pins`, T009-r04.md:41-43); r05 R1 (existência+formato aceitos sem conferir tipo+conteúdo: autoria com fonte de outra família, pin com fonte que não contém o pin, papéis exigidos de PROJECT.md quando deveriam vir da solicitação, T009-r05.md:41-44). O próprio Checker nomeia isso: *"É a quarta rodada consecutiva com achado da classe 'procedência das entradas' [...] pelo escalonamento consultivo (regra em T010, N padrão 3), o Orquestrador classifica uma fase consultiva antes de qualquer novo rework"* (T009-r05.md:30). Este texto que você está lendo agora é, evidentemente, essa fase consultiva.

## 2. Causa recorrente

O protótipo define "origem" como **localização que resolve** — arquivo existe, âncora bate por slug exato, linha existe (`check_provenance_and_id`, T009-mechanical-check.py:233-296; `resolve_provenance_source`:474-543) — nunca como uma relação **tipo de informação → fonte autorizada para esse tipo → conteúdo que sustenta o valor específico**. Não há modelo de dados que categorize os campos por tipo de fonte exigida; cada campo passa pelo mesmo padrão genérico "envelope tem `value`+`source`, `source` resolve". Por isso: `authors` confere se a linha é uma linha de tabela sob cabeçalho "Agent runs" (T009-mechanical-check.py:734-747), mas não se essa linha cita a família declarada; `pins` confere só se o caminho está em PROJECT.md ou numa Task (:673-679), sem comparar o conteúdo com o valor do pin; `roles` exige literalmente `_tl-orc/PROJECT.md` como única fonte válida (:596-599), quando papéis solicitados numa fase deveriam vir da solicitação/spec, não da política. Cada rework fecha o campo/vetor específico que o Checker sondou; o próximo encontra outro campo com a mesma lacuna — é enumeração, não fechamento estrutural.

## 3. Suficiência da spec de T009

AC02 (T009-...md:40) já exige "origem obrigatória" e o ponto 10 do R1-Rework5 na análise (T009-analysis.md:139) já lista fontes por campo, mas em nenhum lugar a spec fixa uma tabela normativa **tipo de informação → fonte autorizada → conteúdo mínimo que deve estar presente na fonte → como conferir esse conteúdo (não só a localização)**. Falta exatamente isso — e é o que o próprio r05 nomeia como pendente ("a procedência é conferida por existência e formato [...] não por tipo e conteúdo", T009-r05.md:42).

Mínimo que fecharia a classe:

Onde deve viver: **T010**, não uma nova Task nem mais uma rodada de T009. Mas a formulação atual de T010 ainda cobre só *tipo de fonte*, não *conferência de conteúdo* — essa tabela deveria ser incorporada a T010 AC02/AC03 antes de fechar T010, já que é lá que a regra distribuída (real, aplicada pelo Orquestrador) vive; o protótipo de T009 é ilustrativo, não a fonte de verdade.

T009 é `analysis`: precisa demonstrar premissas/alternativas/o que mudaria a conclusão (AC05) e piloto reproduzível (AC04/AC06) — não precisa esgotar a classe procedência.
